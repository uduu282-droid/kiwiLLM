# Rate Limits

KiwiLLM applies rate limits to protect shared infrastructure and keep access fair across users.

## Free-tier hosted usage

For the current hosted KiwiLLM free tier, requests are limited to:

- `10 requests per minute`
- `200 requests per day`

<Callout type="info">
	These limits apply to Kiwi-managed hosted usage for free-tier organizations.
	They are enforced by the gateway and can return both minute and day quota
	headers.
</Callout>

## Paid and provider-key traffic

Higher-throughput traffic can still be constrained by:

- your account balance or billing mode
- upstream provider limits
- any product-level fairness or safety controls

These requests are not described by the same simple free-tier bucket above.

## Rate limit headers

Responses can include headers like:

```http
X-RateLimit-Limit-Minute: 10
X-RateLimit-Remaining-Minute: 9
X-RateLimit-Limit-Day: 200
X-RateLimit-Remaining-Day: 199
```

These tell you:

- your minute bucket
- your day bucket
- how much quota remains in each window

## Exceeded limit response

If you exceed the active limit, KiwiLLM returns `429 Too Many Requests`.

```json
{
	"error": {
		"message": "Rate limit exceeded. Try again later.",
		"type": "rate_limit_error",
		"code": "rate_limit_exceeded"
	}
}
```

## Best practices

- use backoff and retry logic for `429`s
- monitor the remaining quota headers
- use a project API key per environment so rate limits are easier to reason about
- plan for burst control if you expect production traffic above the free tier
