# Rate Limits

KiwiLLM applies rate limits to protect shared infrastructure and keep access fair across users.

## Free models

Free models typically use tighter limits than paid usage.

### Base limit

For organizations with no paid credit history:

- `5 requests per 10 minutes`

### Elevated limit

For organizations that have added credits:

- `20 requests per minute`

<Callout type="info">
	Elevated limits for free models do not mean those requests are billed. It is a
	rate-limit tier change, not a hidden charge.
</Callout>

## Paid models

Paid models are generally constrained by:

- your account balance or billing mode
- upstream provider limits
- any product-level fairness or safety controls

They are not described by the same simple free-model limit bucket.

## Rate limit headers

Responses can include headers like:

```http
X-RateLimit-Limit: 20
X-RateLimit-Remaining: 19
X-RateLimit-Reset: 1640995200
```

These tell you:

- the current limit
- how many requests remain
- when the window resets

## Exceeded limit response

If you exceed the active limit, KiwiLLM returns `429 Too Many Requests`.

```json
{
	"error": {
		"message": "Rate limit exceeded. Try again later.",
		"type": "rate_limit_error",
		"code": "rate_limit_exceeded"
	}
}
```

## Best practices

- use backoff and retry logic for `429`s
- monitor the remaining quota headers
- use paid models for higher-throughput production traffic
- top up credits if you want the higher free-tier allowance
