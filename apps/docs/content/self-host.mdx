# Self-Host KiwiLLM

KiwiLLM can be self-hosted if you want full control over your infrastructure, provider credentials, and data retention.

This guide is the fastest repo-based path for getting the stack running locally or on your own servers.

## Prerequisites

- Docker and Docker Compose
- Node.js and pnpm
- API keys for the providers you plan to use
- A Postgres and Redis instance if you are deploying outside Docker Compose

## 1 · Clone the repository

```bash
git clone https://github.com/uduu282-droid/kiwiLLM.git
cd kiwiLLM
pnpm install
```

## 2 · Configure environment

Create a root `.env` file with the values your deployment needs. At minimum, you should define:

```bash
AUTH_SECRET=replace-me
DATABASE_URL=postgresql://...
REDIS_HOST=localhost
REDIS_PORT=6379
HOSTED=true

LLM_OPENAI_API_KEY=
LLM_ANTHROPIC_API_KEY=
LLM_GOOGLE_AI_STUDIO_API_KEY=
```

If you are running a custom provider or worker-backed model, set the corresponding `LLM_*` environment values as well.

## 3 · Start infrastructure

```bash
docker compose up -d
```

This brings up the local Postgres and Redis services defined by the repository.

## 4 · Initialize the app

```bash
pnpm setup
```

That command installs dependencies, syncs the database, seeds local data, and prepares the development environment.

## 5 · Run the stack

```bash
pnpm dev
```

Default local services:

- UI: `http://localhost:3002`
- Playground: `http://localhost:3003`
- Code: `http://localhost:3004`
- Docs: `http://localhost:3005`
- Admin: `http://localhost:3006`
- Gateway: `http://localhost:4001`
- API: `http://localhost:4002`

## Provider configuration

You can add whichever provider credentials you need. Common examples:

```text
LLM_OPENAI_API_KEY=
LLM_ANTHROPIC_API_KEY=
LLM_GOOGLE_AI_STUDIO_API_KEY=
LLM_GROQ_API_KEY=
LLM_XAI_API_KEY=
```

## Multiple API Keys and Load Balancing

KiwiLLM supports multiple API keys per provider for load balancing and availability. Use comma-separated values:

```bash
LLM_OPENAI_API_KEY=sk-key1,sk-key2,sk-key3
LLM_ANTHROPIC_API_KEY=sk-ant-key1,sk-ant-key2
```

### Health-Aware Routing

The gateway automatically tracks the health of each API key and routes requests to healthy keys. If a key experiences consecutive errors, it will be temporarily skipped. Keys that return authentication errors (401/403) are permanently blacklisted until restart.

For providers that need additional config, you can supply matching comma-separated values:

```bash
LLM_GOOGLE_VERTEX_API_KEY=key1,key2,key3
LLM_GOOGLE_CLOUD_PROJECT=project-a,project-b,project-c
LLM_GOOGLE_VERTEX_REGION=us-central1,europe-west1,asia-east1
```

## Basic management commands

```bash
# stop local infra
docker compose down

# inspect running infra
docker compose ps

# re-run app setup
pnpm setup

# start all apps in dev mode
pnpm dev
```

## Next steps

Once KiwiLLM is running:

1. Open the dashboard at `http://localhost:3002`
2. Create an organization and project
3. Generate an API key
4. Test requests against `http://localhost:4002/v1/chat/completions`
5. Add provider keys or hosted provider env vars as needed
