# Reasoning

KiwiLLM supports reasoning-capable models that can spend extra compute on harder prompts such as math, planning, code analysis, and multi-step problem solving.

You can browse reasoning-enabled models on the [Models page](https://kiwillm.in/models?filters=1&reasoning=true).

## Controlling reasoning effort

You can set reasoning in two ways.

### Top-level `reasoning_effort`

```bash
curl -X POST "https://api.kiwillm.in/v1/chat/completions" \
  -H "Authorization: Bearer $KIWILLM_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-oss-120b",
    "messages": [
      {
        "role": "user",
        "content": "What is 2/3 + 1/4 + 5/6?"
      }
    ],
    "reasoning_effort": "medium"
  }'
```

Common values:

- `low`
- `medium`
- `high`
- `xhigh`

Some models may also support `minimal` or provider-specific variants.

### `reasoning.effort`

```bash
curl -X POST "https://api.kiwillm.in/v1/chat/completions" \
  -H "Authorization: Bearer $KIWILLM_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-5",
    "messages": [
      {
        "role": "user",
        "content": "Explain the tradeoffs in this architecture."
      }
    ],
    "reasoning": {
      "effort": "medium"
    }
  }'
```

<Callout type="warning">
	Do not send both `reasoning_effort` and `reasoning.effort` in the same
	request.
</Callout>

## Reasoning token budgets

Some models support explicit reasoning budgets through `reasoning.max_tokens`:

```bash
curl -X POST "https://api.kiwillm.in/v1/chat/completions" \
  -H "Authorization: Bearer $KIWILLM_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "anthropic/claude-sonnet-4-20250514",
    "messages": [
      {
        "role": "user",
        "content": "Explain the P vs NP problem."
      }
    ],
    "reasoning": {
      "max_tokens": 8000
    }
  }'
```

If a model does not support explicit budgets, KiwiLLM returns a validation error instead of silently ignoring the field.

## Usage tracking

Reasoning requests can include additional usage fields like:

- `reasoning_tokens`
- `prompt_tokens`
- `completion_tokens`
- `total_tokens`

This makes it easier to understand how much of a response cost came from reasoning versus final output.

## Streaming

Reasoning-capable models also work with streaming. Depending on the provider, reasoning content may be surfaced separately or may remain internal while only the final answer is streamed.

## Best practices

- use `low` or `medium` first
- increase effort only where the answer quality clearly benefits
- monitor token usage on expensive workflows
- pair reasoning with an explicit reasoning-capable model such as `minimax-m1`

<Callout type="info">
	Not every provider exposes reasoning content in the exact same way. KiwiLLM
	normalizes the request path, but the returned reasoning detail can still vary
	by model family.
</Callout>
