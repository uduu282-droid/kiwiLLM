# Cost Breakdown

KiwiLLM includes cost information directly in API responses so you can measure usage programmatically without polling the dashboard.

<Callout type="info">
	Cost fields are available when the model/provider path supports pricing
	metadata in hosted KiwiLLM.
</Callout>

## Response format

Cost data appears inside the `usage` object:

```json
{
	"usage": {
		"prompt_tokens": 10,
		"completion_tokens": 15,
		"total_tokens": 25,
		"cost_usd_total": 0.000125,
		"cost_usd_input": 0.000025,
		"cost_usd_output": 0.0001,
		"cost_usd_cached_input": 0,
		"cost_usd_request": 0,
		"cost_usd_data_storage": 0.00000025
	}
}
```

## Cost fields

| Field                   | Meaning                                                |
| ----------------------- | ------------------------------------------------------ |
| `cost_usd_total`        | Total inference cost in USD                            |
| `cost_usd_input`        | Input token cost                                       |
| `cost_usd_output`       | Output token cost                                      |
| `cost_usd_cached_input` | Cached input token cost, when applicable               |
| `cost_usd_request`      | Per-request pricing cost for models that bill that way |
| `cost_usd_data_storage` | Storage cost when data retention is enabled            |

## Important distinction

`cost_usd_total` tracks inference cost. Storage cost is separate and only appears when retention-related storage is in play.

## Streaming

Streaming responses include the cost fields in the final usage chunk before `[DONE]`.

## Example with the OpenAI SDK

```ts
import OpenAI from "openai";

const client = new OpenAI({
	apiKey: process.env.KIWILLM_API_KEY,
	baseURL: "https://api.kiwillm.in/v1",
});

const response = await client.chat.completions.create({
	model: "gpt-4o",
	messages: [{ role: "user", content: "Hello!" }],
});

const usage = response.usage;

console.log("total", usage?.cost_usd_total);
console.log("input", usage?.cost_usd_input);
console.log("output", usage?.cost_usd_output);
```

## Common use cases

- budget monitoring
- per-user or per-project allocation
- model comparison
- provider comparison
- automated cost reporting

## Retention and storage cost

When data retention is enabled, KiwiLLM may store request and response payloads for observability and debugging. That storage cost is reported separately from inference cost so your accounting stays clear.

If you are using hosted KiwiLLM with retention enabled, make sure you monitor storage-related spend as well as inference spend.

<Callout type="success">
	Cost breakdown is one of the easiest ways to build usage caps, alerts, and
	internal chargeback logic on top of KiwiLLM.
</Callout>
