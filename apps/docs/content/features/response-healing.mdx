# Response Healing

Response Healing is a KiwiLLM plugin for structured-output workflows. It validates and repairs malformed JSON when a model gets close to the right shape but returns formatting mistakes.

This is especially useful when a model:

- wraps JSON in markdown fences
- adds extra explanatory text
- leaves trailing commas
- truncates output before closing braces

## Enabling the plugin

Add `response-healing` to the `plugins` array:

```bash
curl -X POST "https://api.kiwillm.in/v1/chat/completions" \
  -H "Authorization: Bearer $KIWILLM_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-4o",
    "messages": [
      {
        "role": "user",
        "content": "Return a JSON object with name and age."
      }
    ],
    "response_format": { "type": "json_object" },
    "plugins": [{ "id": "response-healing" }]
  }'
```

<Callout type="info">
	Response Healing only matters for structured output flows such as
	`json_object` and `json_schema`.
</Callout>

## What gets repaired

KiwiLLM can apply several repair strategies:

- extract JSON from markdown code blocks
- strip surrounding prose
- fix common JSON syntax mistakes
- close truncated braces or brackets where possible

## Example with `json_schema`

```ts
const response = await fetch("https://api.kiwillm.in/v1/chat/completions", {
	method: "POST",
	headers: {
		Authorization: `Bearer ${process.env.KIWILLM_API_KEY}`,
		"Content-Type": "application/json",
	},
	body: JSON.stringify({
		model: "gpt-4o",
		messages: [{ role: "user", content: "Generate a user profile." }],
		response_format: {
			type: "json_schema",
			json_schema: {
				name: "user_profile",
				schema: {
					type: "object",
					required: ["name", "email"],
					properties: {
						name: { type: "string" },
						email: { type: "string" },
						age: { type: "number" },
					},
				},
			},
		},
		plugins: [{ id: "response-healing" }],
	}),
});
```

## Limits

Response Healing helps with formatting problems. It cannot reliably fix fundamentally wrong content or schema violations where the model never returned the right data in the first place.

It works best when:

- your prompt already asks clearly for JSON
- the model is usually close to valid output
- you still validate critical fields in your own application

<Callout type="warning">
	Response Healing is not a substitute for application-level validation. Treat
	it as a resilience layer, not your only safety check.
</Callout>

## Best practices

- combine it with strong structured prompts
- prefer `json_schema` when your workflow has strict requirements
- validate final payloads in your application code
- watch logs if healing triggers too often, because that usually means prompts need tightening
