# Image Generation

KiwiLLM supports image generation through OpenAI-compatible image endpoints as well as chat-based image models.

## Supported paths

KiwiLLM supports three main patterns:

1. `/v1/images/generations` for standard image generation
2. `/v1/images/edits` for image editing
3. `/v1/chat/completions` for conversational image-capable models

## Find image models

Browse image-capable models on the [Models page](https://kiwillm.in/models?filters=1&imageGeneration=true).

## Basic image generation

### curl

```bash
curl -X POST "https://api.kiwillm.in/v1/images/generations" \
  -H "Authorization: Bearer $KIWILLM_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gemini-3-pro-image-preview",
    "prompt": "A cute cat wearing a tiny top hat",
    "n": 1,
    "size": "1024x1024"
  }'
```

### OpenAI SDK

```ts
import OpenAI from "openai";
import { writeFileSync } from "fs";

const client = new OpenAI({
	apiKey: process.env.KIWILLM_API_KEY,
	baseURL: "https://api.kiwillm.in/v1",
});

const response = await client.images.generate({
	model: "gemini-3-pro-image-preview",
	prompt: "A futuristic city skyline at sunset with flying cars",
	n: 1,
	size: "1024x1024",
});

response.data.forEach((image, i) => {
	if (image.b64_json) {
		writeFileSync(`image-${i}.png`, Buffer.from(image.b64_json, "base64"));
	}
});
```

## Image editing

You can edit images with `/v1/images/edits` using either hosted image URLs or base64 data URLs.

```bash
curl -X POST "https://api.kiwillm.in/v1/images/edits" \
  -H "Authorization: Bearer $KIWILLM_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "images": [
      {
        "image_url": "https://example.com/source-image.png"
      }
    ],
    "prompt": "Add a watercolor effect to this image",
    "model": "gemini-3-pro-image-preview",
    "quality": "high",
    "size": "1024x1024"
  }'
```

<Callout type="warning">
	Support for individual image-edit parameters depends on the upstream model and
	provider.
</Callout>

## Chat completions with image models

Some image-capable models also work through `/v1/chat/completions`, which is useful when image generation is part of a conversational flow.

```bash
curl -X POST "https://api.kiwillm.in/v1/chat/completions" \
  -H "Authorization: Bearer $KIWILLM_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gemini-3-pro-image-preview",
    "messages": [
      {
        "role": "user",
        "content": "Generate an image of a golden retriever playing in a sunny meadow"
      }
    ]
  }'
```

Generated images are typically returned as base64-backed image data inside the assistant response.

## Practical notes

- image responses can be large, especially as base64 payloads
- supported sizes and quality options vary by model
- image generation is usually more expensive than text-only inference
- some providers support image generation only through specific endpoints

## Best next step

If you are implementing image features in production, test the exact model and parameter set you plan to use. Image support varies more across providers than text support.
