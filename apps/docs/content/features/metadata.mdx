# Metadata

KiwiLLM lets you send additional request metadata using custom headers. This is useful when you want to attach business context like tenant IDs, app versions, user identifiers, or feature names to every request.

That metadata can then be used for filtering, analysis, and internal reporting.

## Header format

Use the `X-KiwiLLM-` prefix:

```bash
curl -X POST "https://api.kiwillm.in/v1/chat/completions" \
  -H "Authorization: Bearer $KIWILLM_API_KEY" \
  -H "Content-Type: application/json" \
  -H "X-KiwiLLM-Country: US" \
  -H "X-KiwiLLM-User-ID: 9403f741-a524-4b18-b1b2-dbb71cdff2a4" \
  -d '{
    "model": "gpt-4o",
    "messages": [
      {
        "role": "user",
        "content": "Hello, how are you?"
      }
    ]
  }'
```

## Good metadata examples

- `X-KiwiLLM-Tenant-ID`
- `X-KiwiLLM-User-ID`
- `X-KiwiLLM-App-Version`
- `X-KiwiLLM-Feature`
- `X-KiwiLLM-Region`

## Multi-tenant example

```bash
curl -X POST "https://api.kiwillm.in/v1/chat/completions" \
  -H "Authorization: Bearer $KIWILLM_API_KEY" \
  -H "Content-Type: application/json" \
  -H "X-KiwiLLM-Tenant-ID: acme-corp" \
  -H "X-KiwiLLM-User-ID: user-12345" \
  -H "X-KiwiLLM-App-Version: 2.1.4" \
  -H "X-KiwiLLM-Feature: chat-assistant" \
  -d '{
    "model": "gpt-4o",
    "messages": [
      {
        "role": "user",
        "content": "Summarize this document."
      }
    ]
  }'
```

## Best practices

### Keep naming consistent

- use clear names
- prefer hyphen-separated keys
- avoid one-off labels that are hard to aggregate later

### Be careful with sensitive data

- avoid raw secrets
- hash or anonymize personal identifiers when appropriate
- follow your own privacy and compliance rules

### Keep values useful

Only send metadata you will actually use. Good metadata helps answer questions like:

- which tenant generated the most spend?
- which feature is driving traffic?
- which app version has the worst latency?

## Recommended use cases

- cost allocation by tenant or customer
- debugging traffic from a specific app version
- internal analytics by product feature
- filtering logs for one user, team, or region

Metadata is most useful when it reflects stable dimensions you already care about in your product analytics.
