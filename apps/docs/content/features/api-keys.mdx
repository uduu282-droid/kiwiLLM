# API Keys and IAM Rules

API keys are how your apps authenticate requests to KiwiLLM. Each key belongs to a project and can be managed independently for usage, access, and lifecycle.

## What API keys support

- Create multiple keys per project
- Revoke or disable keys without deleting the project
- Track usage per key
- Apply IAM rules to models, providers, and pricing access
- Set usage limits when you want a hard cap

## Create an API key

Today, the main way to create keys is from the dashboard:

1. Open your project in [app.kiwillm.in](https://app.kiwillm.in)
2. Go to **API Keys**
3. Click **Create API Key**
4. Give the key a name or description
5. Optionally set a usage limit
6. Save the key and copy it immediately

API keys are shown in full only once when they are created, so store them before closing the dialog.

## Use an API key

Send the key in the `Authorization` header:

```bash
curl -X POST "https://api.kiwillm.in/v1/chat/completions" \
  -H "Authorization: Bearer kiwillm_your_api_key_here" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-4o",
    "messages": [{"role": "user", "content": "Hello from KiwiLLM"}]
  }'
```

## Lifecycle and limits

Keys can be active, disabled, or deleted. Disabled keys can be re-enabled later, while deleted keys should be treated as permanently unusable.

Usage is tracked per key in the dashboard. If you configure a usage limit, KiwiLLM rejects new requests once that limit is reached.

## IAM rules

IAM rules let you restrict:

- which models a key can access
- which providers a key can access
- whether a key can use free or paid models

Older keys without IAM rules continue to work. If you add IAM policies to an existing project, roll them out gradually and monitor denied requests before tightening access further.
