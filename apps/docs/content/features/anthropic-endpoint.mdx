# Anthropic API Compatibility

KiwiLLM exposes an Anthropic-compatible `/v1/messages` endpoint so you can keep Anthropic-style tooling while accessing the broader KiwiLLM catalog.

This is useful for Claude-oriented tools and any client that expects Anthropic request and response formats.

## What it does

KiwiLLM transforms Anthropic message requests into the internal routing format, sends them through the gateway, and returns an Anthropic-style response.

That means you can:

- keep Anthropic-compatible client code
- route to models outside Anthropic when you want to
- use KiwiLLM routing and analytics without changing the client contract

## Claude Code setup

```bash
export ANTHROPIC_BASE_URL=https://api.kiwillm.in
export ANTHROPIC_AUTH_TOKEN=kiwillm_your_api_key_here

# optional
export ANTHROPIC_MODEL=gpt-5
export ANTHROPIC_SMALL_FAST_MODEL=gpt-5-nano

claude
```

## Model selection

You can use any compatible model from the KiwiLLM catalog. Common examples:

```bash
export ANTHROPIC_MODEL=gpt-5
export ANTHROPIC_MODEL=gpt-5-mini
export ANTHROPIC_MODEL=gemini-2.5-pro
export ANTHROPIC_MODEL=claude-3-5-sonnet-20241022
```

Browse the full catalog on the [Models page](https://kiwillm.in/models).

## Manual request example

```bash
curl -X POST "https://api.kiwillm.in/v1/messages" \
  -H "Authorization: Bearer $KIWILLM_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-5",
    "messages": [
      {"role": "user", "content": "Hello, how are you?"}
    ],
    "max_tokens": 100
  }'
```

If you just want the standard OpenAI-compatible path, use `/v1/chat/completions` instead. Use `/v1/messages` when you specifically want Anthropic compatibility.
