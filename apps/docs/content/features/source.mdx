# Source Attribution

The `X-Source` header lets you tag requests with the domain or application that originated them.

This is useful when you want cleaner attribution in logs, usage analysis, or public ecosystem reporting.

## Basic example

```bash
curl -X POST "https://api.kiwillm.in/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $KIWILLM_API_KEY" \
  -H "X-Source: example.com" \
  -d '{
    "model": "gpt-4o",
    "messages": [
      {
        "role": "user",
        "content": "Hello, how are you?"
      }
    ]
  }'
```

## Accepted formats

These all normalize to the same source:

- `example.com`
- `https://example.com`
- `https://www.example.com`
- `www.example.com`

## Good use cases

- separating traffic from multiple frontend apps
- tracking usage by customer domain
- attributing public integrations
- organizing internal analytics by source application

## Best practices

- use stable domains or app identifiers
- avoid sending sensitive user-specific data in this header
- keep the value human-readable so logs stay easy to scan

If you need richer per-request business context, combine this with [Metadata](/features/metadata).
