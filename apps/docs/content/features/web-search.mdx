# Native Web Search

KiwiLLM supports native web search on models that expose web access through the provider. This is useful for current events, live data, research, and any question where freshness matters.

Browse supported models on the [Models page](https://kiwillm.in/models?filters=1&webSearch=true).

## Basic usage

Add the `web_search` tool to the request:

```bash
curl -X POST "https://api.kiwillm.in/v1/chat/completions" \
  -H "Authorization: Bearer $KIWILLM_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-5.2",
    "messages": [
      {
        "role": "user",
        "content": "What is the current weather in San Francisco?"
      }
    ],
    "tools": [
      {
        "type": "web_search"
      }
    ]
  }'
```

When the model decides a search is needed, it will fetch current information and include citations in the response.

## Common options

### User location

Provide location context when local relevance matters:

```json
{
	"type": "web_search",
	"user_location": {
		"city": "San Francisco",
		"region": "California",
		"country": "US",
		"timezone": "America/Los_Angeles"
	}
}
```

### Search context size

Some providers let you control how much web context is retrieved:

```json
{
	"type": "web_search",
	"search_context_size": "medium"
}
```

Supported values are typically:

- `low`
- `medium`
- `high`

### Max uses

Limit how many searches the model can make during one request:

```json
{
	"type": "web_search",
	"max_uses": 3
}
```

## OpenAI SDK example

```ts
import OpenAI from "openai";

const client = new OpenAI({
	apiKey: process.env.KIWILLM_API_KEY,
	baseURL: "https://api.kiwillm.in/v1",
});

const response = await client.chat.completions.create({
	model: "gpt-5.2",
	messages: [
		{
			role: "user",
			content: "What are the latest AI product launches this week?",
		},
	],
	tools: [{ type: "web_search" }],
});

console.log(response.choices[0].message.content);
```

## Streaming

Web search also works with streaming:

```bash
curl -X POST "https://api.kiwillm.in/v1/chat/completions" \
  -H "Authorization: Bearer $KIWILLM_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-5.2",
    "messages": [
      {
        "role": "user",
        "content": "What is the latest price of Bitcoin?"
      }
    ],
    "tools": [{ "type": "web_search" }],
    "stream": true
  }'
```

## Citations

Search-backed responses may include citations in the assistant message annotations. This gives you a direct reference to the URLs used during response generation.

<Callout type="info">
	Citation shape can vary slightly by provider, but KiwiLLM keeps the request
	and response format OpenAI-compatible.
</Callout>

## Best practices

- use web search only on models that support it
- provide location context when the question is local
- review citations in user-facing workflows
- monitor web-search cost separately from token cost when available

## Typical use cases

- current events
- live prices and market data
- weather
- factual lookup with citations
- real-time research assistants

<Callout type="warning">
	If you try to use `web_search` on a model that does not support it, the
	request will fail. Check the filtered models list first when wiring this into
	production apps.
</Callout>
