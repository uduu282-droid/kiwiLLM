If you are already using the Vercel AI SDK, moving to KiwiLLM is mainly about changing the provider setup while keeping the overall `generateText` or `streamText` flow intact.

## Quick migration

```diff
- import { openai } from "@ai-sdk/openai";
+ import { createLLMGateway } from "@llmgateway/ai-sdk-provider";

+ const llmgateway = createLLMGateway({
+   apiKey: process.env.KIWILLM_API_KEY
+ });

const { text } = await generateText({
- model: openai("gpt-4o"),
+ model: llmgateway("gpt-5"),
  prompt: "Hello!"
});
```

## Steps

<Steps>
<Step>
### Install the provider package

```bash
pnpm add @llmgateway/ai-sdk-provider
```

</Step>

<Step>
### Set your API key

```bash
export KIWILLM_API_KEY=kiwillm_your_key_here
```

</Step>

<Step>
### Update your AI SDK code

```ts
import { createLLMGateway } from "@llmgateway/ai-sdk-provider";
import { generateText } from "ai";

const llmgateway = createLLMGateway({
	apiKey: process.env.KIWILLM_API_KEY,
});

const { text } = await generateText({
	model: llmgateway("gpt-5"),
	prompt: "Hello!",
});
```

</Step>
</Steps>

## Streaming example

```ts
import { createLLMGateway } from "@llmgateway/ai-sdk-provider";
import { streamText } from "ai";

const llmgateway = createLLMGateway({
	apiKey: process.env.KIWILLM_API_KEY,
});

const result = await streamText({
	model: llmgateway("claude-sonnet-4-5"),
	prompt: "Write a short poem about code review.",
});
```

## Model selection

You can use:

- routed root model IDs like `gpt-5`
- fixed upstream IDs like `openai/gpt-5`

Check the [Models page](https://kiwillm.in/models) for the current catalog.

## Why use KiwiLLM here

- one provider layer across vendors
- dashboard visibility for request usage
- routing and fallback support
- easier model switching without changing the rest of the app architecture
