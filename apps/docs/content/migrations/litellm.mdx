LiteLLM and KiwiLLM both expose OpenAI-compatible APIs, so the migration is mostly a base URL and API key change.

## Quick migration

```diff
- const baseURL = "http://localhost:4000/v1";
- const apiKey = process.env.LITELLM_API_KEY;
+ const baseURL = "https://api.kiwillm.in/v1";
+ const apiKey = process.env.KIWILLM_API_KEY;
```

## Why teams make this move

- fewer moving parts to operate
- hosted API keys and dashboard flows
- built-in request logs and cost visibility
- routing, fallback, and caching in one product

## Steps

<Steps>
<Step>
### Create a KiwiLLM API key

Create a hosted key from [API Keys](https://app.kiwillm.in/dashboard/settings/api-keys).

</Step>

<Step>
### Update your client configuration

#### Python

```python
from openai import OpenAI

client = OpenAI(
    base_url="https://api.kiwillm.in/v1",
    api_key=os.environ["KIWILLM_API_KEY"]
)
```

#### TypeScript

```ts
import OpenAI from "openai";

const client = new OpenAI({
	baseURL: "https://api.kiwillm.in/v1",
	apiKey: process.env.KIWILLM_API_KEY,
});
```

</Step>

<Step>
### Keep or simplify model IDs

You can use:

- root model IDs like `gpt-5`
- provider-prefixed IDs like `openai/gpt-5`

Browse the current catalog on the [Models page](https://kiwillm.in/models).

</Step>
</Steps>

## Example request

```bash
curl https://api.kiwillm.in/v1/chat/completions \
  -H "Authorization: Bearer $KIWILLM_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-5",
    "messages": [
      {
        "role": "user",
        "content": "Hello!"
      }
    ]
  }'
```

## Self-hosted option

If you still want to self-host, KiwiLLM supports that too:

```bash
git clone https://github.com/uduu282-droid/kiwiLLM.git
cd kiwiLLM
pnpm install
docker compose up -d
pnpm setup
pnpm dev
```
