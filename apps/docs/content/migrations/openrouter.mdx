If you already use OpenRouter, KiwiLLM should feel familiar. The migration is mostly updating your endpoint and API key.

## Quick migration

```diff
- const baseURL = "https://openrouter.ai/api/v1";
- const apiKey = process.env.OPENROUTER_API_KEY;
+ const baseURL = "https://api.kiwillm.in/v1";
+ const apiKey = process.env.KIWILLM_API_KEY;
```

## Steps

<Steps>
<Step>
### Create a KiwiLLM key

Create a key in the KiwiLLM dashboard.

</Step>

<Step>
### Update environment variables

```bash
KIWILLM_API_KEY=kiwillm_your_key_here
```

</Step>

<Step>
### Point your client to KiwiLLM

#### fetch

```ts
const response = await fetch("https://api.kiwillm.in/v1/chat/completions", {
	method: "POST",
	headers: {
		Authorization: `Bearer ${process.env.KIWILLM_API_KEY}`,
		"Content-Type": "application/json",
	},
	body: JSON.stringify({
		model: "gpt-5",
		messages: [{ role: "user", content: "Hello!" }],
	}),
});
```

#### OpenAI SDK

```ts
import OpenAI from "openai";

const client = new OpenAI({
	baseURL: "https://api.kiwillm.in/v1",
	apiKey: process.env.KIWILLM_API_KEY,
});
```

</Step>
</Steps>

## Model IDs

Many migration flows work best if you start with root model IDs like:

- `gpt-5`
- `claude-sonnet-4-5`
- `gemini-2.5-pro`

If you want a specific upstream, use provider-prefixed IDs like `openai/gpt-5`.

## Why migrate

- request and cost visibility in one dashboard
- unified routing layer
- API key management in the product
- a managed hosted setup with less operational overhead
