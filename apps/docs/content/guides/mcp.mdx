KiwiLLM exposes an MCP server so MCP-compatible clients can access models and tools through one hosted endpoint.

## Available capabilities

The hosted MCP server can expose capabilities such as:

- chat completions
- model discovery
- image generation on supported models

## Endpoint

Use:

```text
https://api.kiwillm.in/mcp
```

Authentication uses the same API key you use for the REST API.

## Setup

<Tabs items={["Claude Code", "Codex", "Cursor", "Other MCP Clients"]}>
  <Tab value="Claude Code">
    <Steps>
    <Step>
    ### Create an API key

    Get a KiwiLLM API key from the dashboard.

    </Step>

    <Step>
    ### Add the server

    ```bash
    claude mcp add --transport http --scope user kiwillm https://api.kiwillm.in/mcp \
      --header "Authorization: Bearer your-api-key-here"
    ```

    </Step>
    </Steps>

  </Tab>

  <Tab value="Codex">
    <Steps>
    <Step>
    ### Export your API key

    ```bash
    export KIWILLM_API_KEY="your-api-key-here"
    ```

    </Step>

    <Step>
    ### Add the MCP server

    ```bash
    codex mcp add kiwillm --url https://api.kiwillm.in/mcp \
      --bearer-token-env-var KIWILLM_API_KEY
    ```

    </Step>
    </Steps>

  </Tab>

  <Tab value="Cursor">
    Add an MCP entry that points to:

    ```json
    {
      "mcpServers": {
        "kiwillm": {
          "url": "https://api.kiwillm.in/mcp",
          "headers": {
            "Authorization": "Bearer your-api-key-here"
          }
        }
      }
    }
    ```

  </Tab>

  <Tab value="Other MCP Clients">
    Use:

    - **Endpoint:** `https://api.kiwillm.in/mcp`
    - **Auth:** `Authorization: Bearer <api-key>`

    Example:

    ```bash
    curl -X POST https://api.kiwillm.in/mcp \
      -H "Content-Type: application/json" \
      -H "Authorization: Bearer your-api-key" \
      -d '{
        "jsonrpc": "2.0",
        "id": 1,
        "method": "tools/list"
      }'
    ```

  </Tab>
</Tabs>

## Notes

- the hosted MCP endpoint shares your normal KiwiLLM account auth
- MCP support depends on the client supporting HTTP transport
- available tools can evolve as the hosted gateway changes

## Troubleshooting

- confirm your API key works against the REST API first
- confirm the client supports Streamable HTTP MCP
- if tools do not appear, reconnect the MCP server in the client

<Callout type="info">
	If you need filesystem write paths or local upload directories for image
	workflows, that is a better fit for a self-hosted gateway deployment than the
	shared hosted endpoint.
</Callout>
