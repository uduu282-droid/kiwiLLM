Cursor supports OpenAI-compatible endpoints, so you can connect it to KiwiLLM and choose from the broader KiwiLLM model catalog without changing your editor workflow.

![Cursor with KiwiLLM](/guides/cursor/overview.png)

## Prerequisites

- a KiwiLLM API key
- Cursor installed

## Setup

<Steps>
<Step>
### Create an API key

Create a key from [API Keys](https://app.kiwillm.in/dashboard/settings/api-keys).

</Step>

<Step>
### Open Cursor model settings

In Cursor:

1. open **Settings**
2. open **Cursor Settings**
3. go to **Models**

</Step>

<Step>
### Add the KiwiLLM connection

Set:

- **API Key**: your KiwiLLM key
- **Override OpenAI Base URL**: `https://api.kiwillm.in/v1`

</Step>

<Step>
### Pick your model

Select any supported model from the [Models page](https://kiwillm.in/models), for example:

- `gpt-5`
- `gpt-4o`
- `claude-sonnet-4-5`
- `gemini-2.5-pro`

</Step>
</Steps>

## Notes

- use direct model IDs for normal routing
- use provider-prefixed models if you want one exact upstream
- make sure the model name matches the KiwiLLM catalog, not just the native vendor UI

## Troubleshooting

### Authentication error

- verify the API key
- verify the base URL is `https://api.kiwillm.in/v1`

### Model not found

- check the exact model ID on the [Models page](https://kiwillm.in/models)
- try a simpler known-good model like `gpt-5` first

### Slow responses

- try a smaller model for autocomplete
- use stronger models only for chat or more complex edits

<Callout type="info">
	Cursor works best when you separate “fast everyday model” and “strong chat
	model” choices instead of using one expensive model for every feature.
</Callout>
