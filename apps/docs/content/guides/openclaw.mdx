[OpenClaw](https://docs.openclaw.ai/) can route its traffic through KiwiLLM as a custom OpenAI-compatible provider. This gives you one API entry point, KiwiLLM usage tracking, and access to the wider model catalog.

## Setup

<Steps>
<Step>
### Create an API key

Create a KiwiLLM API key from the dashboard.

</Step>

<Step>
### Export the key

```bash
export KIWILLM_API_KEY=kiwillm_your_api_key_here
```

</Step>

<Step>
### Add KiwiLLM as a provider

Configure OpenClaw with a custom provider that points to KiwiLLM:

```json
{
	"models": {
		"mode": "merge",
		"providers": {
			"kiwillm": {
				"baseUrl": "https://api.kiwillm.in/v1",
				"apiKey": "${KIWILLM_API_KEY}",
				"api": "openai-completions",
				"models": [
					{ "id": "gpt-5", "name": "GPT-5" },
					{ "id": "claude-sonnet-4-5", "name": "Claude Sonnet 4.5" },
					{ "id": "gemini-2.5-pro", "name": "Gemini 2.5 Pro" }
				]
			}
		}
	},
	"agents": {
		"defaults": {
			"model": {
				"primary": "kiwillm/gpt-5"
			}
		}
	}
}
```

</Step>

<Step>
### Start OpenClaw

Launch OpenClaw normally. Requests will flow through KiwiLLM.

</Step>
</Steps>

## Why use KiwiLLM here

- unified API key and billing surface
- central usage tracking
- model flexibility
- optional provider fallback and routing

## Switching models

Update the configured model to any supported KiwiLLM model from the [Models page](https://kiwillm.in/models).

```json
{
	"agents": {
		"defaults": {
			"model": {
				"primary": "kiwillm/claude-sonnet-4-5"
			}
		}
	}
}
```

<Callout type="info">
	OpenClaw configuration differs by version, so treat the provider block above
	as the KiwiLLM connection pattern and adjust field names if your installed
	OpenClaw release expects a slightly different schema.
</Callout>
