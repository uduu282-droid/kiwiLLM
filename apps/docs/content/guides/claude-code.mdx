Claude Code expects Anthropic-compatible APIs. KiwiLLM supports that format natively through `/v1/messages`, which means you can keep the Claude Code workflow and still route requests to the wider KiwiLLM model catalog.

## Setup

<Steps>
<Step>
### Create an API key

Create a KiwiLLM API key from your dashboard:

- [Dashboard](https://app.kiwillm.in/dashboard)
- [API Keys](https://app.kiwillm.in/dashboard/settings/api-keys)

</Step>

<Step>
### Set the environment variables

```bash
export ANTHROPIC_BASE_URL=https://api.kiwillm.in
export ANTHROPIC_AUTH_TOKEN=kiwillm_your_api_key_here
export ANTHROPIC_MODEL=gpt-5
```

You can replace `gpt-5` with any compatible model from the [Models page](https://kiwillm.in/models).

</Step>

<Step>
### Run Claude Code

```bash
claude
```

Claude Code will keep speaking Anthropic format, and KiwiLLM will handle the routing behind the scenes.

</Step>
</Steps>

## Why this works

KiwiLLM exposes an Anthropic-compatible messages endpoint, so Claude Code can:

- keep the same request format
- use models outside Anthropic when you want them
- show usage and cost in the KiwiLLM dashboard

## Useful model choices

```bash
# Higher-end model
export ANTHROPIC_MODEL=gpt-5

# Faster / cheaper model
export ANTHROPIC_MODEL=gpt-5-mini

# Claude through KiwiLLM
export ANTHROPIC_MODEL=anthropic/claude-3-5-sonnet-20241022

# Gemini through KiwiLLM
export ANTHROPIC_MODEL=gemini-2.5-pro
```

## Direct test request

```bash
curl -X POST "https://api.kiwillm.in/v1/messages" \
  -H "Authorization: Bearer $KIWILLM_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-5",
    "messages": [
      {
        "role": "user",
        "content": "Hello, how are you?"
      }
    ],
    "max_tokens": 100
  }'
```

<Callout type="info">
	If you want deterministic upstream behavior, use provider-prefixed model IDs
	like `openai/gpt-5` or `anthropic/claude-3-5-sonnet-20241022`.
</Callout>
