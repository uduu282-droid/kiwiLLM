[OpenCode](https://opencode.ai) can use KiwiLLM through an OpenAI-compatible provider definition, which makes it easy to swap models while keeping one API surface.

## Prerequisites

- OpenCode installed
- a KiwiLLM API key

## Setup

<Steps>
<Step>
### Create the provider config

Create or update your OpenCode config file:

```json
{
	"provider": {
		"kiwillm": {
			"npm": "@ai-sdk/openai-compatible",
			"name": "KiwiLLM",
			"options": {
				"baseURL": "https://api.kiwillm.in/v1"
			},
			"models": {
				"gpt-5": { "name": "GPT-5" },
				"gpt-5-mini": { "name": "GPT-5 Mini" },
				"gemini-2.5-pro": { "name": "Gemini 2.5 Pro" },
				"claude-sonnet-4-5": { "name": "Claude Sonnet 4.5" }
			}
		}
	},
	"model": "kiwillm/gpt-5"
}
```

</Step>

<Step>
### Launch OpenCode

```bash
opencode
```

</Step>

<Step>
### Connect the provider

Use the OpenCode connect flow and provide your KiwiLLM API key when prompted.

</Step>
</Steps>

## Good defaults

- use `gpt-5` for strong coding help
- use `gpt-5-mini` for cheaper iteration
- add provider-prefixed models only when you want a fixed upstream

## Troubleshooting

### 404 errors

Make sure the base URL is exactly:

```text
https://api.kiwillm.in/v1
```

### Model not found

Check the exact model name on the [Models page](https://kiwillm.in/models).

### Repeated auth prompts

Verify the provider key in your config is stable and matches the one OpenCode expects.

<Callout type="info">
	OpenCode’s exact config schema can evolve between releases, so the important
	part is the KiwiLLM connection pattern: OpenAI-compatible provider, base URL
	set to KiwiLLM, and model IDs from the KiwiLLM catalog.
</Callout>
